## 1. Evaluation set

Both models' existing held-out predictions, matched on the visit pair
(patient, current visit, next visit), then restricted to cases eligible for the
binary task:

| | |
|---|---|
| Shared visit pairs | 3,352 |
| **Eligible, identical rows for both models** | **3,020** |
| Patients | 898 |
| Actual PIGD | 910 (30.1%) |
| Actual TD | 2,110 |

Actual Indeterminate targets are excluded, as everywhere else in the project.
Row alignment between the two tables is asserted, as is agreement on the actual
label, so both models are scored on exactly the same cases in the same order.

AUC was computed with scikit-learn and cross-checked against the project's own
rank-based implementation; the two agree to machine precision.

## 2. Results

| Model | AUC | 95% CI (patients resampled) |
|---|---|---|
| **Rich clinical profile** | **0.8902** | **0.8748 – 0.9053** |
| CT-HMM | 0.8583 | 0.8411 – 0.8755 |
| Persistence rule (reference) | 0.7927 | 0.7725 – 0.8127 |

**Paired difference, rich profile − CT-HMM: +0.0319, 95% CI +0.0229 to +0.0419.**

**The interval excludes zero.** On ranking ability the rich profile is better,
and this is the first metric in the project on which the two methods separate.

Intervals resample patients, not predictions — a patient with many visits
contributes many correlated rows, and a row-level bootstrap would be too narrow.

The persistence rule emits only 0 and 1, so it has a single operating point
rather than a curve; its "AUC" is just its balanced accuracy and is shown for
reference, not as a curve comparison.

---

## 3. Why AUC separates the models when accuracy does not

This does **not** contradict the manuscript's finding that the two are
indistinguishable on accuracy (+0.0033, CI −0.0050 to +0.0112). The two
metrics measure different things, and the figure shows exactly where they part:

- The curves are **almost identical at the low-false-positive end**, which is
  where the argmax decision rule operates. Accuracy only ever reads that one
  point, so it sees no difference.
- They **separate through the middle of the curve**, at operating points no
  threshold-0.5 rule ever visits. AUC integrates over all of them, so it sees
  the difference clearly.

Put plainly: the rich profile *orders* patients by PIGD risk better, but at the
specific threshold used for classification that better ordering does not convert
into more correct calls — because the subtype label is strongly persistent and
most cases sit far from the boundary in both models.

This is consistent with everything else measured:

| Metric | Verdict |
|---|---|
| Accuracy | indistinguishable (+0.0033, CI spans zero) |
| Brier | rich profile better (0.1177 vs 0.1215) |
| Log loss | rich profile better (0.3766 vs 0.3963) |
| **AUC** | **rich profile better, CI excludes zero** |

Three of the four probability-quality measures favour the rich profile; only
accuracy — the one metric that discards the probabilities — does not.

## 4. AUC within each current label

| Current label | n | n PIGD | CT-HMM | Rich profile |
|---|---|---|---|---|
| TD | 2,074 | 252 | 0.6680 | **0.7798** |
| Indeterminate | 268 | 121 | 0.6305 | **0.6794** |
| PIGD | 678 | 537 | 0.6649 | **0.7437** |

The rich profile is ahead **within every stratum**, so its advantage is not an
artefact of the marginal class mix.

**These numbers are not comparable to the pooled AUC above.** The pooled 0.86–0.89
is largely driven by the current label itself, which separates TD from PIGD
strongly. Conditioning on it removes that easy signal and leaves the genuinely
hard part of the problem — which is why every stratified AUC is far lower. The
honest reading is that *most* of the pooled discrimination is "the subtype
rarely changes", and the residual ranking skill is modest for both models,
though clearly better for the rich profile.

---

## 5. What this changes

**It refines, not overturns, the manuscript.** The manuscript's statement that
the two methods are statistically indistinguishable is about **accuracy on the
subtype endpoint**, and that remains exactly true. But it would now be
incomplete to leave it there: on a threshold-free ranking measure the rich
profile is significantly better, with an interval excluding zero.

Suggested amendment to §6.1 and the abstract — a sentence, not a rewrite:

> The two methods are statistically indistinguishable on accuracy (+0.0033,
> 95% CI −0.0050 to +0.0112), but the rich profile ranks cases significantly
> better (AUC 0.890 against 0.858; paired difference +0.032, 95% CI +0.023 to
> +0.042). Accuracy reads a single operating point on a near-saturated,
> thresholded endpoint; the probability-quality measures do not, and three of
> them favour the rich profile.

This also reinforces the recommendation from the AIC/BIC note: **prefer
continuous scores over accuracy for model selection in this project.** Accuracy
has now failed to detect a difference that AUC, Brier, log loss and the
information criteria all find.

---

## 6. Limitations

- AUC is **invariant to calibration**: it measures ranking only. A model can
  rank perfectly and still be badly calibrated. Brier and log loss, reported in
  the manuscript, cover that and also favour the rich profile.
- The two models' predictions come from **different validation schemes**
  (leave-one-patient-out for the CT-HMM, repeated 5-fold CV for the rich
  profile). Matching the cases removes the evaluation-set difference but not
  the scheme difference, and that caveat carries over from the manuscript.
- **Indeterminate targets are excluded**, so this is a binary evaluation over
  90.1% of prediction opportunities, as elsewhere.
- The stratified AUCs in §4 use the same data for stratification and
  evaluation; they are descriptive and carry no multiplicity correction.
- The persistence rule's AUC is not a curve-based figure and should not be
  compared with the other two as though it were.
- Patient-level bootstrap intervals are percentile intervals from 2,000 draws;
  no bias correction was applied.
